# デモ動画の生成マニュアル

Web版を実際のローカルバックエンドにつなぎ、Playwrightで操作・録画します。Bashスクリプトを1回実行すると、通常版と15秒ショート版の両方を生成します。Linuxで動作確認しています。GUIやElectronの起動、手動ログインは不要です。

## 初回セットアップ

必要なものはBash、Node.js 22.13以降、npm、Python 3、Google Chrome、Playwright、FFmpeg（libx264とlibass対応）、fontconfig、Noto Sans CJK JPです。

Ubuntu / Debianでの準備例（Node.jsとnpmは導入済みの場合）：

```bash
sudo apt-get update
sudo apt-get install -y python3 ffmpeg fontconfig fonts-noto-cjk
# リポジトリのルートで実行
npm ci
npx playwright install --with-deps chrome ffmpeg
bash artifacts/demo/generate.sh --check
```

Playwright用のFFmpegはブラウザ録画に、OS側のFFmpegは字幕合成・MP4変換に使います。初回インストールはネット接続が必要です。通常の生成はローカルで完結します。

`--check` はコマンド、Node.jsのバージョン、Playwrightの読み込み、FFmpegの機能、日本語フォントを確認します。Chromeの起動とローカルサーバーへの接続は、実際の録画時に確認します。

## 通常版・15秒版をまとめて生成

```bash
bash artifacts/demo/generate.sh
```

別のディレクトリからスクリプトの絶対パスを指定しても実行できます。録画は約80秒、変換を含む所要時間は目安で1〜3分です。処理能力や負荷によって変わります。同時に複数実行しないでください。同名の成果物は上書きするため、残したい動画は先にコピーしてください。

処理は、依存関係の確認 → 専用サーバー起動 → UI操作・録画 → 保存内容の確認 → 両方のMP4生成 → 動画の形式・長さ・デコード確認、の順に進みます。途中で失敗した場合は非ゼロの終了コードで止まります。

| 出力先（リポジトリ基準）                   | 内容                                                           |
| ------------------------------------------ | -------------------------------------------------------------- |
| `artifacts/demo/best-todo-demo.mp4`        | 通常版：約77秒。実行時の操作時間によって多少変わります         |
| `artifacts/demo/best-todo-demo-short.mp4`  | ショート版：15秒。主要操作6場面を各2.5秒に編集                 |
| `artifacts/demo/recording.webm`            | 再編集用の元録画。デモ用ログイン画面も含みます                 |
| `artifacts/demo/chapters.json`             | 章の開始時刻と保存確認結果                                     |
| `artifacts/demo/initial.png` / `final.png` | 開始・終了時の画面                                             |
| `artifacts/demo/error.png`                 | UI操作失敗時の画面。以前の失敗時のファイルが残ることがあります |

生成した動画・画像・字幕・計測データはこのディレクトリの `.gitignore` でGitの追跡対象から除外しています。スクリプトとマニュアルは追跡できます。

MP4は両方とも横長1440×900、30fps、H.264、日本語字幕付き・音声なしです。操作位置を丸いマーカーで表示します。ショート版は場面をカットし、一部を早送りします。縦長のSNS動画ではありません。

## 録画済みの素材から再生成

字幕やショート版の場面選択だけを変更するときは、録画を省略できます。

```bash
bash artifacts/demo/generate.sh --render-only
```

同じ成功した録画から得た `recording.webm` と `chapters.json` の両方が必要です。録画が途中で失敗した場合はこのモードを使わず、引数なしで撮り直してください。

```bash
bash artifacts/demo/generate.sh --help
```

## 収録内容と確認項目

通常版は、リスト作成、タスク登録、ステップ・期限・詳細メモ、完了、メモ登録、表の列追加と登録、検索、期限順への切り替え、再読み込み後の保存確認を収録します。

録画時に、再読み込み後のタスク3件・メモ1件・表1件、期限、詳細メモ、ステップの完了状態、画面のJavaScriptエラーがないことを確認します。生成後は両動画のH.264形式・解像度・デコード、およびショート版が15秒であることを確認します。

## データと実行環境

既存の `.env` は読み込まず、専用の認証情報と `/tmp/best-todo-demo-*` の一時DBを使用します。既存DBとアプリのソースは変更しません。サーバーは `127.0.0.1` の空きポートで起動し、通常終了時に停止します。完成MP4からデモ用ログイン部分を取り除きます。

一時DB、ブラウザ録画の作業ファイル（`artifacts/demo/recordings/`）は残ります。不要になった分は、実行終了後に削除できます。OSから強制終了した場合、子プロセスが残ることがあるため確認してください。

## 内容を変更する

| ファイル      | 編集する内容                                                           |
| ------------- | ---------------------------------------------------------------------- |
| `record.mjs`  | 入力データ、UIの操作順、各場面の待ち時間、通常版の章タイトル、保存確認 |
| `render.py`   | 字幕スタイル、MP4の設定、ショート版の場面範囲・字幕                    |
| `generate.sh` | 依存関係確認、録画・変換の実行、完成動画の検証                         |

日付は撮影時の例として `2026-10-09` / `10月9日` を使用しています。別の日付にする場合は、`record.mjs` の入力値・表の表示・保存確認の期待値をまとめて変更してください。章の順番を変える場合は、`render.py` の `scenes` が参照する章番号も合わせて更新します。

## トラブル時の対処

| 症状                                                   | 対処                                                                                                                 |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| `playwright` が見つからない                            | リポジトリのルートで `npm ci` を実行                                                                                 |
| Chromeや録画用FFmpegが見つからない、共有ライブラリ不足 | `npx playwright install --with-deps chrome ffmpeg` を実行                                                            |
| `libx264` / `ass` がない                               | libx264・libass対応のOS側FFmpegを導入                                                                                |
| 日本語フォントのエラー                                 | `fonts-noto-cjk` を導入し、`fc-cache -f` の後に再確認                                                                |
| `listen EPERM` / `EACCES`                              | 実行環境でローカルサーバーの待受とブラウザ起動を許可する。制限付きエージェント環境では権限承認が必要な場合があります |
| UI操作のタイムアウト                                   | `error.png` とエラーログを確認し、画面変更に合わせて `record.mjs` の対象要素や待ち時間を調整                         |
| `--render-only` で素材がない                           | まず引数なしで録画から実行                                                                                           |
